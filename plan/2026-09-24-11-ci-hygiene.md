Settled at intent approval (15fb5b0) and spec approval (1604b1d):

- **CI (E1).** `.github/workflows/check.yml`:
  - Triggers: `pull_request`, and `push` to `main`.
  - `permissions: contents: read`, and no secrets.
  - `concurrency` per ref with `cancel-in-progress`.
  - One `ubuntu-latest` job with `timeout-minutes: 45`:
    1. `actions/checkout`, pinned by SHA.
    2. A udev rule that makes `/dev/kvm` mode 0666, then `udevadm trigger`.
    3. `cachix/install-nix-action`, pinned by SHA, with
       `system-features = nixos-test benchmark big-parallel kvm`.
    4. `nix flake check -L`.
  - **Fallback,** only if the VM test fails twice on `main` with no code
    cause: `nix flake check -L --no-build`, then `nix build -L` of
    `checks.x86_64-linux.{shellcheck,cli,manifest,no-hardcoded-colours,module-gating}`,
    with the VM test run by hand. It is written in the workflow as a comment.
- **Hardening the reconcile unit (E2).** The unit stays `User=root`, because
  snapd authorizes clients by peer UID. It gets:
  - `NoNewPrivileges`;
  - an empty `CapabilityBoundingSet` and `AmbientCapabilities`;
  - `ProtectSystem = "strict"`, with the existing `StateDirectory` the only
    writable path;
  - `ProtectHome`, `PrivateTmp` and `PrivateDevices`;
  - `ProtectKernelTunables`, `ProtectKernelModules`, `ProtectKernelLogs`,
    `ProtectControlGroups`, `ProtectClock` and `ProtectHostname`;
  - `RestrictAddressFamilies = [ "AF_UNIX" ]`;
  - `RestrictNamespaces`, `LockPersonality`, `RestrictRealtime` and
    `RestrictSUIDSGID`;
  - `MemoryDenyWriteExecute`;
  - `SystemCallArchitectures = "native"` and
    `SystemCallFilter = [ "@system-service" ]`;
  - `UMask = "0077"`.

  The reason each is safe is in the spec's D2 table. A directive that breaks a
  real snap operation is dropped with a comment naming the operation.
  `DynamicUser`, polkit, `ProtectSystem = "full"` and `IPAddressDeny` are
  rejected.
- **VM test (`checks.module`).** Two new assertions:
  - a `systemd-analyze security --threshold=<measured score, rounded up>` floor;
  - the unit's journal names `hello-world` and contains none of
    `Permission denied`, `Read-only file system` or `Operation not permitted`.

## Rollback

- **Code and docs:** revert the PR's merge commit. Each step is its own commit,
  so one part can be reverted alone. For example, revert step 6 if the
  hardening misbehaves on a host after nixarchy bumps the input. nixarchy can
  also stay on its current pin.
- **CI:** delete or disable the workflow. Nothing depends on it.
- **razer:** `sudo /nix/var/nix/profiles/system/bin/switch-to-configuration test`
  returns to `G0`'s configuration. No generation is created, so none needs
  deleting. If `hello-world` is left behind, `sudo snap remove --purge hello-world`.
  Post the state on the agent bus.
- **`nixosModules.flatsnap`:** if a consumer turns up, restore the one line
  `flatsnap = ./module.nix;`.

## Open

- **A real take for `record.sh`'s generation cleanup.** Only a full recording
  on razer proves it: the desktop is driven, and two applies create
  generations. This plan does not run one. The change is checked by shellcheck
  and review, and the PR says it is unproven. A take on razer needs the user's
  go-ahead.
- **An older nixarchy without the `flatsnap.nix` copy, with the module
  imported,** would now pass preflight, and its apply would copy nothing. This
  is acceptable, since the plugin ships only with nixarchy after #914. It is
  written here so the deletion is a known ceiling, not an oversight.
