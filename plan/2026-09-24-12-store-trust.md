# Plan: show what a user needs to trust an app before it is queued

## Approved decisions (self-contained)

**Scope.** This change is about what the user is shown and asked, nothing
else. It does not touch the apply path, the state file, the NixOS module, or
the reconciler's behaviour.

**Unknown permissions.**
- `lookup_flatpak` sets `permissions: null` when the Flathub summary fetch
  fails. It no longer falls back to `{}`.
- A summary that loads but lists no permissions stays `{}`, and the card
  still says "permissions: none listed".
- For `null`, the card shows
  `permissions: UNKNOWN (the Flathub lookup failed)` in `Color.urgent`.

**Publisher verification: a label only.**
- There is no second Enter and no urgent colour for an unverified publisher.
- Every card and search row gets `verified` (`true` / `false` / `null`, where
  `null` means unknown) and `verifiedAs` (a string).
- **Flathub card:** read from the appstream document already fetched. There
  is no extra request.
  - `metadata["flathub::verification::verified"] == true` → `true`.
    `verifiedAs` is `::website`, or else `::login_name (::login_provider)`.
  - Key present with value `null` or `false` → `false`.
  - Key absent, or no `metadata` → `null`.
- **Flathub search:** `verification_verified` (absent → `null`).
- **Snap card and search:** `publisher.validation`. `"verified"` → `true`.
  Any other value (`"unproven"`, `"starred"`) → `false`. Absent → `null`.
- **Card display:** the publisher gets its own line, and license moves to the
  next line.
  - `publisher: X — verified (<verifiedAs>)`
  - `publisher: X — not verified by Flathub` (or `by the Snap Store`)
  - `publisher: X — verification UNKNOWN` in `Color.urgent`
- **Search and "ask" rows:** append `   verified` or `   unverified`, and
  nothing for `null`.
- All of this is plain text in a `Line`, never markup.

**Sandbox-escaping overrides: a fixed, documented list in the CLI.**
- The list is one jq literal next to `OV_RE`, repeated in the README:

  | Section.key | Values |
  |---|---|
  | `Context.filesystems` | `host`, `host-os`, `host-etc`, `home`, `~` |
  | `Context.sockets` | `session-bus`, `system-bus`, `ssh-auth`, `gpg-agent` |
  | `Context.devices` | `all` |
  | `Session Bus Policy.org.freedesktop.Flatpak` | `talk`, `own` |
  | `System Bus Policy.*` (any name) | `talk`, `own` |

- A value matches only when it equals a listed value after any `:ro`, `:rw`
  or `:create` suffix is stripped. `~/Games`, `home/x`, `!host` and `xdg-*`
  do not match.
- `features=devel` is not on the list (decided at spec approval).
- Every flatpak card carries `sandboxEscapes: [{section, key, values, says}]`.
  The model checks overrides against it synchronously.
- A card without the list treats every override as escaping: it fails loud.
- `add flatpak` does not refuse listed overrides.
- The prompts:
  - A listed override: `Enter again: <id> ESCAPES its sandbox — <override>: <says>`.
  - Any other override: today's prompt, unchanged.

**Every classic snap confirms on Enter.**
- `overridesArmed` is renamed `queueArmed`. It covers classic snaps and
  flatpak overrides.
- A snap with `classic == true` arms on the first Enter with
  `Enter again: install <id> WITHOUT a sandbox (classic confinement)`, and
  writes on the second Enter.
- This applies whether the store or the user (`x x`) chose classic, so the
  user path takes four presses.
- `_showCard`, `cycleChannel`, `toggleClassic` and `disarm()` clear
  `queueArmed`, and editing the overrides still disarms. `Menu.qml`'s key
  filter and footer use the new name.

**Removal says the data is deleted.**
- For a snap, the prompt is
  `y removes <id> at the next apply and DELETES its data (no snapshot); any other key keeps it`,
  and the row suffix is `← y removes it and its data`.
- The flatpak prompt is unchanged.
- The reconciler's `--purge` stays.

**Out of scope, as follow-up issues opened after merge:**
- accessibility (`Accessible.role` / `Accessible.name` on the list rows and
  card)
- highlighting escaping permissions in the app's own manifest

**Merge order.** #11 → #13 → #10 → #12. This branch merges last and builds on
#10's version of `FlatsnapModel.qml`. #10 gates `queue()`, `remove()` and
apply on `applying`, and reworks message handling.

Line numbers below are for origin/main (64f97b2). After step 1 they will
move, so find the code by function name.

## Rollback

- The change is confined to the CLI's lookup and search output, two QML
  files, fixtures, tests and the README. No state format, Nix module or
  generated `flatsnap.nix` changes, so nothing on a machine needs migrating.
- Before merge: drop the branch.
- After merge: `git revert` the merge commit (or the squash commit), and
  reinstall the plugin as usual on razer to check.
- The older CLI and new QML combine safely. A card without `sandboxEscapes`
  warns on every override, and a missing `verified` shows UNKNOWN. So a
  partial rollback fails loud, not open.
