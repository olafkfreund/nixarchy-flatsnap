# Plan: menu text follows the desktop's scale

The menu's text is `Style.font.caption` / `Style.font.subtitle` × a fixed
1.45 (`Menu.qml:22-23`, used at `:52` and `:189`). The shell's font tokens
already follow `[font] base-size` in `~/.config/omarchy/shell.toml` (set by
`omarchy display text size`). Monitor scale is applied by the compositor to
text and window alike, since QML sizes are logical pixels. So the 1.45 stacks on the
text-size setting and keeps the menu 45% larger than the shell. The window
geometry (`Menu.qml:25-31, 59, 72-75`) is already right and is not touched.

**Decided at intent approval:**

1. Text is scale-aware: no flat multiplier on top of `Style.font`; sizes
   come from the shell's `Style` tokens.
2. The menu stays larger than the shell only by a scale-aware step (a bigger
   `Style.font` token).
3. This repo fixes its own `Menu.qml`; sibling plugins get follow-up issues.

**Decided at spec approval:**

4. Body text uses `Style.font.title` (base-size × 1.167) and the card title
   uses `Style.font.heading` (× 1.333). The smaller default is accepted:
   15 → 14px and 19 → 16px at base-size 12, and 25 → 23px and 32 → 27px
   at base-size 20.
5. The two input fields (`TextField` at `Menu.qml:160` and `:208`) are raised
   from the shell `qs.Ui` default `Style.font.body` to `Style.font.title`, to
   match the body text. Their height follows (`Ui/TextField.qml`: sizing is
   `font.pixelSize` + `verticalPadding`).
6. A shared "menu text" token in upstream omarchy is a follow-up, not in
   scope.
7. `no-text-multiplier` flake check guards against the multiplier coming
   back.

Nothing else changes: keys, colours, layout, `FlatsnapModel.qml`, `bin/`.

## Steps

1. `Menu.qml:22-23`: delete `readonly property real textScale: 1.45` and
   `function px(base)`. → verify by `grep -nE 'textScale|px\(' Menu.qml`
   printing nothing.
2. `Menu.qml:52` (`component Line`): `font.pixelSize: Style.font.title`.
   → verify by `grep -n 'pixelSize' Menu.qml` showing this line.
3. `Menu.qml:189` (card title `Line`): `font.pixelSize: Style.font.heading`.
   → verify by the same grep.
4. `Menu.qml:160` (`field`) and `:208` (`ovField`): add
   `font.pixelSize: Style.font.title`. → verify by the same grep: exactly
   four `pixelSize` lines, all `Style.font.*`.
5. `flake.nix`, after `no-hardcoded-colours` (`:94-100`): add
   `checks.no-text-multiplier`, a `runCommand` that fails if
   `grep -nE 'textScale|uiScale|px\(' ${./Menu.qml}` matches, or if any
   `pixelSize:` line in `Menu.qml` is not
   `pixelSize: Style\.font\.[A-Za-z]+` followed by `;`, `}`, whitespace or end
   of line. Error message: "fixed text multiplier; use a Style.font token".
   → verify by `nix flake check -L` passing, and failing on a scratch copy
   with `textScale` restored (negative test, not committed).
6. Code commit on `fix/9-text-scale`: `fix(menu): text follows the shell's
   text size (#9)`, citing steps 1-5.
7. Razer, never p620: dev install and manual check (see Tests 3-4).
   Screenshots at two monitor scales go into the PR.
8. PR against `main` linking the intent, spec and this plan, with the
   before/after size table from decision 4 and the screenshots.
9. **Only after the PR is merged:** open one issue in each sibling repo,
   each linking #9 and the spec:
   - `olafkfreund/nixarchy-pkg`: "Menu text ignores the desktop's text size
     (fixed 1.45 multiplier)" (`Menu.qml:35`, `textScale`)
   - `olafkfreund/nixarchy-devenv`: same title (`Menu.qml:32`)
   - `olafkfreund/nixarchy-distrobox`: same title (`Menu.qml:30`)
   - `olafkfreund/nixarchy-plugin-browser`: same title (`Menu.qml:27`,
     `uiScale`)
   → verify by `gh issue list` in each repo showing the new issue.

## Tests

1. `nix flake check -L`: all checks pass, including `no-text-multiplier`,
   `no-hardcoded-colours`, `shellcheck` and `manifest`.
2. `tests/model.sh` prints `model: N passed, 0 failed`. It tests
   `FlatsnapModel.qml`, which is untouched, so a pass shows nothing next to
   the change broke.
3. QML load, on razer: after the dev install (stage the built plugin
   outside `~/.config/omarchy/plugins/`, then `mv` it in; a file-by-file
   copy wedges the live shell), open the menu and check the shell's log has
   no QML error for `Menu.qml` (no `ReferenceError: px`). *Deviation from
   the spec:* the spec had this as `quickshell -p` in the style of
   `tests/model.sh`, but `Menu.qml` imports `qs.Commons` and `qs.Ui`, which
   only resolve inside the running shell, so the load check is done there.
4. Manual, razer:
   - Monitor scale 1 and 2 (or razer's native fractional scale): open the
     menu, look up an app, open Declared, focus both input fields. Text,
     fields and window scale together; nothing is clipped.
   - `omarchy display text size 16`, then `20`, with the menu open: text
     and fields re-flow live and keep the same size relative to the bar.
     Then `omarchy display text size reset`.
   - Expected at base-size 12: body text and fields 14px, card title 16px.
