# Plan: let the panel's overrides field take a Bus Policy override

## Approved decisions (self-contained)

**Problem.** The panel's overrides field is split on whitespace
(`FlatsnapModel.qml:214`, `overrides.trim().split(/\s+/)`). A section that
contains spaces, such as `Session Bus Policy` or `System Bus Policy`, is cut
into pieces. The CLI accepts these sections (`OV_SEC='[A-Za-z][A-Za-z ]{0,40}'`,
`bin/nixarchy-flatsnap:20`), and both are on `ESCAPES_JSON` (`:38-39`).
Today the panel cannot queue them, and it does not warn about them.

**Scope.** Only `FlatsnapModel.qml` `queue()` changes, plus two comments,
the README and the tests. `bin/nixarchy-flatsnap` is not changed: `OV_*`,
`cmd_add`, `check_entries` and `ESCAPES_JSON` stay as they are. The
`Menu.qml` placeholder and the Declared list stay as they are.

**Decisions.**
1. **Separator: whitespace, as today.** The field is tokenised by matching
   whole overrides from left to right, with the CLI's grammar:
   ```js
   /^\s*([A-Za-z][A-Za-z ]{0,40}\.[A-Za-z0-9_.-]{1,100}=[A-Za-z0-9_.\/:~!@+=-]{1,200})(?=\s|$)/
   ```
   The regex is applied to the remaining slice again and again.
   - It has no sticky flag and no lookbehind.
   - A section ends at the first `.`, a key at the first `=`, and a value
     at the next whitespace.
   - A value that is too long, or has a character outside the grammar,
     fails the match. It is not cut short.
2. **Existing input tokenises the same.** Any input where every
   whitespace token matches `OV_RE` gives the same tokens as today.
   Example: the placeholder
   `Context.filesystems=xdg-pictures:ro  Environment.LC_ALL=C.UTF-8`.
3. **Text that does not parse.** The first Enter sets the message
   `"Not an override: <rest> (Section.key=value, separated by spaces)"`.
   - It does not arm and does not write.
   - `<rest>` is the text from the first part that fails, to the end. It
     is cut at 60 characters, with "…" added.
   - The message is in the normal colour, because nothing is armed. The
     CLI still validates on the second Enter.
4. **Bus Policy escapes.**
   `Session Bus Policy.org.freedesktop.Flatpak=talk|own` and
   `System Bus Policy.<any>=talk|own` get the red ESCAPES wording and the
   second Enter. `_escapes()` needs no change for this: its regex already
   allows spaces in a section.
5. **Accepted at spec approval: a stray word can become part of a
   section.** In `foo Context.x=y`, the section is `foo Context`. The CLI
   accepts it (same grammar), and flatpak ignores an unknown section. The
   first Enter lists each override, so the user sees it before anything
   is written.
6. **Accepted at spec approval: the panel keeps its own copy of the
   `OV_*` grammar.** A comment in each place names the other. The CLI
   does not send the grammar to the panel.
7. **Accepted at spec approval: listing format.** The ordinary first-Enter
   message joins overrides with `", "` (was `"  "`). The ESCAPES message
   keeps `"; "`.

**Merge order.** #36 → **#28** → #27 → #26. This branch merges second. It
is rebased onto `main` after #36 merges, and #27 rebases onto it.

**Hosts.**
- `tests/model.sh` needs a Wayland session, and it is not in CI. It runs on
  razer, with stubbed `nixarchy-apply`.
  *Deviation (user decision, 2026-09-25):* it runs on p620's Wayland
  session, under `tests/isolate.sh`. That script's PATH cannot reach the
  real `nixarchy-apply`.
- The manual check runs on razer, reserved by the user.
- Nothing is applied or preflighted, and nothing runs on p620.
