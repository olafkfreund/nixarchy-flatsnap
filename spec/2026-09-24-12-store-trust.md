# Spec: show what a user needs to trust an app before it is queued

## Decisions carried from the intent

| # | Question | Decision |
|---|---|---|
| Q1 | Second Enter for an unverified publisher? | No. A label on the card and on search rows only |
| Q2 | Which overrides escape the sandbox? | A fixed, documented list in the CLI. These get an urgent warning and the second Enter; every other override keeps today's prompt |
| Q3 | Accessibility (intent item 6) | Split out as a follow-up issue, not opened by this work |

Also approved with the intent:
- When the summary lookup fails, the card shows permissions as UNKNOWN in
  `Color.urgent`.
- Every classic snap needs the second Enter, whether the store or the user
  chose classic.
- The removal prompt says that the snap's data is deleted.

Line numbers are for origin/main (64f97b2).

## Design

### D1: Unknown permissions (`bin/nixarchy-flatsnap`, `Menu.qml`)

`lookup_flatpak` (`:109-118`) keeps the appstream lookup as the thing that
decides whether the app exists. The summary fetch no longer falls back to
`'{}'`. When it fails, the card gets `permissions: null`:

```
s=$(fetch ... summary ...) || s=null
permissions: (if $s == null then null else ($s.metadata.permissions // {}) end)
```

A summary that loads but lists no permissions stays `{}` and still reads
"permissions: none listed". The two cases can no longer be confused.

`FlatsnapModel.qml:107` tests `r.permissions !== undefined` to tell a full
card from a search hit. `null` passes that test, so this needs no change.

`Menu.qml:194-202`: when `c.permissions === null`, the Line reads
`permissions: UNKNOWN (the Flathub lookup failed)` with
`color: Color.urgent`. Otherwise the text is unchanged and the colour stays
the default.

### D2: Publisher verification (`bin/nixarchy-flatsnap`, `Menu.qml`)

Each store's answer is mapped to two fields on every card and search row:
`verified` (`true` | `false` | `null`), where `null` means "we could not
tell", and `verifiedAs` (a string, possibly empty).

**Flathub card** comes from the appstream document the plugin already
fetches. No extra request is made. The live data checked on 2026-09-24 agrees
with `/api/v2/verification/<id>/status` for the apps sampled (firefox,
Calculator, OBS, Discord verified; Spotify, VS Code not):

| `metadata` in appstream | `verified` | `verifiedAs` |
|---|---|---|
| `"flathub::verification::verified": true` | `true` | `flathub::verification::website`, or else `login_name` + ` (` + `login_provider` + `)` |
| key present, value `null` or `false` (Spotify: every `flathub::verification::*` is `null`) | `false` | `""` |
| key absent, or no `metadata` object | `null` | `""` |

The key-absent case gives `null` rather than `false`, so a change to the
document's shape shows as unknown and not as unverified.

**Flathub search** (`search_flathub`, `:173-179`): each hit already carries
`verification_verified` (bool) and `verification_website`. Absent maps to
`null`.

**Snap card and search** (`lookup_snap` `:130`, `search_snap` `:185-187`):
both already request `publisher`. The mapping is:
`verified: (if .publisher.validation == null then null else .publisher.validation == "verified" end)`
and `verifiedAs: ""`. `"unproven"` and `"starred"` count as unverified:
starred is a Canonical recognition, not an identity check.

**Display.** On the card (`Menu.qml:191`), the publisher gets its own Line:
- `publisher: GNOME — verified (gnome.org)`
- `publisher: Spotify — not verified by Flathub` (or `by the Snap Store`)
- `publisher: X — verification UNKNOWN` in `Color.urgent`

License moves to the next Line. On list rows (`Menu.qml:260-268`), a search
or "ask" candidate appends `   verified` or `   unverified`. `null` appends
nothing, because the card is where "unknown" is spelled out. Every value is
plain text in a `Line`, as today: `verifiedAs` is store data and is never
treated as markup. There is no colour, prompt or extra key for unverified
publishers (Q1).

### D3: Sandbox-escaping overrides (`bin/nixarchy-flatsnap`, `FlatsnapModel.qml`)

**The list lives in the CLI** as one jq literal next to `OV_RE` (`:306-308`),
with a comment. The same list goes in the README's overrides section:

| Section.key | Values (any `:ro`/`:rw`/`:create` suffix ignored) | Says |
|---|---|---|
| `Context.filesystems` | `host`, `host-os`, `host-etc`, `home`, `~` | "your whole home folder" / "the host filesystem" |
| `Context.sockets` | `session-bus`, `system-bus` | "the whole session bus" / "the system bus" |
| `Context.devices` | `all` | "every device, including cameras and input" |
| `Session Bus Policy.org.freedesktop.Flatpak` | `talk`, `own` | "run commands outside the sandbox" |
| `System Bus Policy.*` (any name) | `talk`, `own` | "talk to system services" |

A value matches when it equals a listed value after the suffix is stripped.
`~/Games`, `home/Documents`, `!host` and `xdg-*` do not match.

The flatpak card JSON carries the list as `sandboxEscapes: [{section, key,
values, says}]`. The CLI stays the one place the list is written, and the
model can check typed overrides without starting a process. `add flatpak`
does not refuse listed overrides: the panel is its only caller, and the
confirmation is the protection.

**In the model** (`queue()`, `:176-188`), each override token is checked
against `card.sandboxEscapes`:
- None match: today's prompt, unchanged
  (`Enter again: change <id>'s sandbox with …`).
- One or more match: the prompt names them and what they grant, for example
  `Enter again: <id> ESCAPES its sandbox — Context.filesystems=home: your whole home folder`.
  The footer already turns `Color.urgent` while any arm flag is set
  (`Menu.qml:300`).

A card without `sandboxEscapes` (an older CLI) treats every override as
listed. Losing the list therefore warns more, never less.

### D4: Every classic snap confirms on Enter (`FlatsnapModel.qml`, `Menu.qml`)

`overridesArmed` is renamed `queueArmed`: "the next Enter queues". It is used
by both stores:
- **snap:** when `classic` is true and `queueArmed` is false, `queue()` sets
  `queueArmed` and the message
  `Enter again: install <id> WITHOUT a sandbox (classic confinement)`, then
  returns. The second Enter queues with `--classic`, as today.
- **flatpak:** as in D3, with the new name.

This applies whichever path set `classic`: the store (`_showCard :114`,
`cycleChannel :136`) or the user (`x x`, `toggleClassic`). The user path
therefore becomes `x x` then `Enter Enter`. That is intended: the approval
names both paths, and the Enter prompt is the only one that names the app
being queued.

A changed card, channel or classic state must not ride on an old arm:
- `_showCard`, `cycleChannel` and `toggleClassic` clear `queueArmed`.
- The existing override-edit disarm stays.
- `disarm()` clears it.
- In `Menu.qml:106-111`, the key filter's `enter && fs.overridesArmed`
  becomes `enter && fs.queueArmed`. The arm list at `:109` and `:300` is
  renamed to match.

### D5: Removal says data is deleted (`FlatsnapModel.qml`, `Menu.qml`)

`remove()` (`:197`) builds its prompt by store:
- **snap:** `y removes <id> at the next apply and DELETES its data (no snapshot); any other key keeps it`.
- **flatpak:** unchanged.

The row suffix (`Menu.qml:267`) for a snap reads
`← y removes it and its data`. The reconciler's `--purge`
(`bin/nixarchy-flatsnap-reconcile:52-57`) is not changed; the reason is in
its comment and in README.md:138.

### D6: Follow-up, not in this change

Accessibility (`Accessible.role` / `Accessible.name` on list rows and the
card, `Menu.qml:249-271`) gets its own issue after this spec is approved. It
is listed in the PR description.

## Alternatives rejected

- **Call `/api/v2/verification/<id>/status` per card.** It works (checked
  live), but it is one more request, fixture and failure mode for data the
  appstream document already contains. It stays the fallback if the appstream
  keys ever disappear, which D2's `null` makes visible.
- **Second Enter for unverified publishers.** Rejected at the intent (Q1).
  Most apps on both stores are unverified, so the prompt would become noise.
- **A `nixarchy-flatsnap overrides …` verb to classify overrides.** It keeps
  the matching in bash, but it makes the first Enter wait on a process and
  adds a state to the arming logic (armed, but the reply has not come back).
  Carrying the list on the card keeps the arming synchronous.
- **`add flatpak` refusing listed overrides unless given a flag.** The panel
  is the only caller and would always pass the flag, so it protects nothing.
- **Colouring every unverified publisher urgent.** It is the same noise as a
  second Enter. Urgent is kept for unknown data and for escapes.
- **Skipping the Enter confirm when the user already pressed `x x`.** That
  keeps two paths to the same unsandboxed install with different warnings,
  which is the thing D3 in the intent complained about.

## Risks

- **Conflicts with #10.** Issue #10 (apply safety) also edits
  `FlatsnapModel.qml` `queue()` and `remove()` to gate on `applying`, and the
  `message` handling around `_run()`. This work touches the arming block in
  `queue()`, the prompt in `remove()`, `disarm()` and the key filter in
  `Menu.qml`. Whichever lands second rebases. The changes are kept to those
  blocks so the conflict is textual, not semantic. Neither change relies on
  the other's gating.
- **Flathub changes the appstream shape.** Verification then shows UNKNOWN,
  in urgent, on every card: loud, not wrong. Fixed by reading the status
  endpoint (the rejected alternative).
- **The escape list is incomplete.** Anything not listed still gets the
  ordinary override prompt. It is never less guarded than today. The list is
  one literal, and adding to it needs a fixture-free cli test only.
- **Existing tests change on purpose.**
  - `tests/cli.sh:96` compares a whole search object, and `tests/model.qml`
    uses `overridesArmed` and treats `Context.filesystems=home` as an
    ordinary override. These are updated, not worked around.
  - `tests/fixtures/flathub-search.json` is the default search fixture and a
    byte copy of `flathub-search-calculator.json` (finding E9, owned by
    another issue). Both gain the verification fields here, so E9's dedupe
    stays trivial.
- **A user-chosen classic takes four presses** (`x x`, `Enter Enter`). This
  is accepted, per the approval.
- No change to the apply path, the state file, the NixOS module or the
  reconciler's behaviour. Nothing runs as root that did not before.

## Verification

**Fixtures** (recorded from the live APIs, trimmed to the fields read, under
`tests/fixtures/`):
- `flathub-appstream-org.gnome.Calculator.json`: add the
  `flathub::verification::*` keys (verified, website `gnome.org`).
- `flathub-appstream-com.spotify.Client.json` and
  `flathub-summary-com.spotify.Client.json`: unverified flatpak, all keys
  `null`.
- `flathub-appstream-org.example.NoSummary.json` with no summary fixture:
  the failed summary lookup. A missing fixture is a failed fetch
  (`fetch`, `:18-29`).
- `flathub-appstream-org.example.NoMeta.json` with no `metadata`:
  verification unknown.
- `snap-info-hello-world.json` and `snap-info-code.json`: add
  `publisher.validation: "verified"`.
- New `snap-info-<unproven snap>.json`: `validation: "unproven"`.
- `flathub-search*.json` and `snap-find.json`: add
  `verification_verified` / `publisher.validation` to the hits.

**`tests/cli.sh`** (offline, run by `nix flake check` via `flake.nix:79`):
- Calculator: `.verified == true and .verifiedAs == "gnome.org"`.
- Spotify: `.verified == false`.
- NoMeta: `.verified == null`.
- NoSummary: `.permissions == null`, exit 0. Calculator keeps
  `(.permissions | type) == "object"`.
- hello-world: `.verified == true`. The unproven snap: `.verified == false`.
- Search on both stores: every row has a `verified` key.
- Every flatpak card has a non-empty `sandboxEscapes`, and each listed row in
  the D3 table is present.

**`tests/model.qml`** (`bash tests/model.sh`, run by hand; it needs Wayland):
- A store-classic snap (`classic: true, confinement: "classic"`): the first
  `queue()` arms, does not write, and the message contains `WITHOUT a sandbox`.
  The second writes with `--classic` on argv.
- A user-classic snap (`x x`) arms the same way on Enter.
- A strict snap queues on one Enter.
- `cycleChannel()` / `toggleClassic()` after arming clears `queueArmed`.
- `Context.filesystems=home`, `Context.sockets=system-bus`,
  `Session Bus Policy.org.freedesktop.Flatpak=talk`: the message contains
  `ESCAPES` and the matched override.
- `Context.filesystems=xdg-pictures:ro` and `~/Games`: the ordinary prompt,
  without `ESCAPES`.
- A card with no `sandboxEscapes`: every override gets the escape wording.
- `remove()` on a snap: the message contains `DELETES its data`. On a
  flatpak it does not.

**Manual, on razer only** (never p620), with the plugin staged as in the
project memory:

  lines and the search-row labels.

  `NIXARCHY_FLATSNAP_OFFLINE=<repo>/tests/fixtures` and paste
