# Spec: show the plugin working, on its own site and on nixarchy's

## Decisions carried from the intent

| # | Question | Decision |
|---|---|---|
| Q1 | Recorder | `gpu-screen-recorder` on razer; no razer config change |
| Q2 | Scripted or by hand | scripted: `docs/record.sh` in this repo |
| Q3 | nixarchy front page | next to Packages |
| Q4 | Apply in the recording | recorded for real, the build log cut to its first and last seconds, and the caption says so |

## Design

### D1: the capture session on razer

razer's screen is **1920x1080 (16:9)**. The largest 16:10 region on it is
**1728x1080 at +96+0**. It scales exactly to nixarchy's 900x563 GIF and to
1280x800 stills, so nothing is cropped afterwards.

The session reuses the setup from olafkfreund/nixarchy#914's step 7, which is
proven there:
- a `/tmp` clone of nixos_config, with nixarchy on the version that ships the
  plugin (#914's branch, or main once merged), and nixos_config's own nix-snapd
  import removed;
- `switch-to-configuration test`, so that the plugin is installed by nixarchy,
  enabled by its post-boot hook, and `nixarchy-apply` carries `flatsnap.nix`;
- `NIXARCHY_FLAKE=<clone>`, so the real apply writes only to the clone.

The desktop is set to nixarchy's documented look for the capture, and restored
afterwards (`docs/AGENTS.md`, "Put the desktop back"):

1. Record `omarchy-theme-current` and `omarchy-theme-bg-current`, then set
   **Tokyo Night** with the **Winding Road** background, which is
   `programs.nixarchy.defaultTheme` and what `00-desktop.jpg` shows.
2. Switch to an **empty workspace**, with nothing translucent over the wallpaper.
3. Turn on **Do Not Disturb**, so no notification lands in a frame.
4. Before recording, take one still of the bare region, and check the bar for
   personal data (mail counts, a playing track, tray items). If anything is
   there, its bar widgets are hidden for the take and restored afterwards; the
   setting changed is recorded in the plan.

### D2: `docs/record.sh` (this repo)

The script runs **on razer**, inside the Hyprland session's environment, which
it takes from the running quickshell's `/proc/<pid>/environ`, as the
end-to-end test did. It is a scenario, not a library: one fixed sequence with
fixed holds.

| Scene | Keys (`wtype`) | Still |
|---|---|---|
| open | `omarchy-shell shell toggle nixarchy.flatsnap` | `01-empty` |
| paste a Flathub link | the URL for `org.gnome.Calculator`, then `Enter` | `02-flatpak-card` |
| queue | `Enter` | — |
| search the Snap Store | `hello`, then `Ctrl+S`, then `j` | `03-snap-search` |
| a Snap card | `Enter` on `hello-world`, then `c` | `04-snap-card` (confinement warning) |
| classic confirm | `x` (armed, red), then `Esc` | `05-classic-confirm` |
| queue the snap | `Esc` back to the card, `c` to stable, `Enter` | — |
| Declared | `Tab` | `06-declared` |
| apply | `a` (build log streams) | `07-apply-log` |
| app launched | close the panel; `flatpak run org.gnome.Calculator` on the region | `08-calculator` |
| remove | reopen, `Tab`, `d`, `y` on each, `a` | — |

- **Recording:** `gpu-screen-recorder -w region -region 1728x1080+96+0 -f 30 -cursor no -o raw.mp4`,
  stopped with SIGINT. The script prints a timestamp at each scene start to
  `scenes.tsv`.
- **Stills:** `grim -g "96,0 1728x1080"`, scaled to **1280x800**, saved as
  `.webp` (quality 85).
- **The apply cut** (Q4): frames between *apply start + 3 s* and
  *applied − 3 s* are dropped, using `scenes.tsv`. The GIF's caption and alt text
  say "build log shortened".
- **Encoding:** ffmpeg decodes to 4 fps PNG frames, with `mpdecimate` and
  `-fps_mode vfr` for held frames (the #889 lesson in `docs/AGENTS.md`). Then
  nixarchy's own `tests/demo/encode-gif.sh <frames> flatsnap.gif`, taken from a
  nixarchy checkout (`NIXARCHY_SRC`, default: `nix flake prefetch github:olafkfreund/nixarchy`'s
  store path), so the encode cannot drift from nixarchy's.
- **Gate:** nixarchy's `tests/demo/verify-frames.sh flatsnap.gif --expect 'Calculator'
  --expect 'Flatpak' --expect 'applied' --forbid 'error|failed|refused' --max-bytes 1000000`.
  A GIF that fails the gate is not committed; the script is fixed and the take
  re-run instead.
- **Clean-up**, always, via `trap`:
  - close the panel;
  - un-declare anything still declared, then apply;
  - restore the theme, background and Do Not Disturb;
  - switch razer back to the generation recorded at the start, and delete the
    test generations;
  - remove `~/.config/nixarchy/flatsnap.nix` and the `enabled-once` marker.

  The generation razer is left on goes to the agent bus.

### D3: the plugin's site and README (this repo)

- **`docs/index.md`:** the hero's `<pre>` text mock and its comment go. The hero
  becomes `img/flatsnap.gif` with alt text describing the flow. The three "Paste
  / Look / Queue, then apply" scenes each get their still (`02`, `04`, `07`), and
  a closing strip carries `05-classic-confirm` and `06-declared`. Each image is
  wrapped in a link to itself, as nixarchy's front page does.
- **`README.md`:** the GIF under the opening paragraph, with a one-line caption.
- **Files:** `docs/img/flatsnap.gif` and `docs/img/0N-*.webp`. The README links
  the GIF by the Pages URL, so there is one copy.

### D4: nixarchy's site and README (a follow-up PR after #914)

It gets its own nixarchy issue, and the PR links this spec, as #906 linked
the plugin's.

- **Files:** `docs/img/features/flatsnap.gif` and
  `docs/img/plugins/flatsnap-{card,snap}.webp`, which are the same files as D3.
- **`docs/manual/plugins.md`:** the Flatpak and Snap section gets the GIF and the
  two stills, in the shape of the GitHub Actions section (a GIF, then stills with
  alt text).
- **`docs/manual/flatpak-and-snap.md`:** the GIF under the opening paragraph, and
  the Snap-card still in *Security*.
- **`docs/index.md`:** in the install section, after `install.gif` and its link,
  a two-sentence paragraph on software nixpkgs does not carry, then the GIF, then
  a link to the manual page. "Panels, not terminals" gets a bullet: *install
  Flatpak and Snap apps from a pasted link*.
- **`README.md`:** the panels grid's first row becomes Packages | Flatpak & Snap,
  and the other panels move down one cell. The sentence "Each is a real session,
  recorded in a VM" becomes "recorded in a VM (Flatpak & Snap: on a test laptop,
  since it needs Flathub and the Snap Store)", which stays true.
- nixarchy's docs checks (`build.yml` lint and `readme-counts.sh`) are run
  locally, as for #914.

## Alternatives rejected

- **`wl-screenrec` on razer** (Q1): a razer config change for no difference in
  output.
- **A nixarchy `tests/demo` VM scenario.** The demo VMs have no network, and
  this flow needs Flathub, the Snap Store and a real apply. nixarchy's
  `encode-gif.sh` mentions that two scenes are already recorded outside the
  sandbox for the same reason.
- **Composing a separately captured panel onto `00-desktop.jpg`.** That is for
  stills of popups. The recording has to be continuous, and setting razer to the
  documented theme gives the same backdrop honestly.
- **Keeping the text mock alongside the media.** The intent says the mock goes.

## Risks

| Risk | Where | Mitigation |
|---|---|---|
| Personal data in a frame (bar widgets, notifications, a translucent window) | razer | Empty workspace, Do Not Disturb, the bar checked before the take (D1.4), and every still plus the verify-frames samples looked at before commit |
| The desktop left changed (theme, wallpaper, generation, a declared app) | razer | `trap` clean-up; values recorded first; bus post with the final generation |
| Another agent is using razer's desktop (ai-mirror recordings) | razer | Read the bus and claim first; hold if anyone has it |
| The GIF goes over 1 MB | both sites | The apply cut, `mpdecimate`, and a 96-colour palette; `--max-bytes` fails it rather than shipping it |
| The OCR gate cannot read the text | both sites | The region is the full 16:10 height, so the panel takes about 70% of the frame; fix the size, not the `--expect` (`docs/AGENTS.md`) |
| The recording goes stale when the UI changes | both sites | `docs/record.sh` re-records in one run |

## Verification

1. `verify-frames.sh` passes on the committed GIF (the expects, the forbid, and
   under 1 MB). Its output is pasted in the PR.
2. Every still and the sampled frames are looked at, with no personal data;
   stated in the PR.
3. The plugin site builds (`jekyll build -s docs`), and after merge the live site
   shows the GIF and the stills (a headless screenshot).
4. razer is back on its starting generation, theme and background (compared
   with the recorded values), with no declared apps. Posted on the bus.
5. The nixarchy follow-up: its docs checks and a Jekyll build are green locally,
   CI is green, and the images render on the live site after merge.
