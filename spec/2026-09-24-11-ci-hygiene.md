# Spec: CI, a hardened root unit, a safe recorder, and plans that match the code

Line numbers are for `main` at 64f97b2. The four questions in the intent were
settled when it was approved:

1. GitHub Actions runs `nix flake check -L` on KVM, with a cheaper set to fall
   back to if the VM test proves flaky.
2. E4 ships a fallback warning, and the dead grep is deleted. The flake-path
   interface becomes a nixarchy follow-up.
3. The plans for #1 and #5 get dated late-deviation notes. They are not
   rewritten.
4. `nixosModules.flatsnap` is dropped.

## Design

### D1: CI (E1)

A new `.github/workflows/check.yml`:

- **Triggers:** `pull_request`, and `push` to `main`.
- **`permissions: contents: read`.** It uses no secrets, no cache credentials
  and no deploy key.
- **`concurrency`:** one run per ref, with `cancel-in-progress: true`, so a
  new push cancels the older run.
- **One job, `ubuntu-latest`, with `timeout-minutes: 45`:**
  1. `actions/checkout`, pinned by commit SHA.
  2. Enable KVM. Add a udev rule that makes `/dev/kvm` mode 0666, then run
     `udevadm trigger`. This is the documented way to use KVM on GitHub's
     Linux runners, which are free for public repositories.
  3. Install Nix with `cachix/install-nix-action`, pinned by SHA, with
     `extra-conf: system-features = nixos-test benchmark big-parallel kvm`.
  4. `nix flake check -L`.

`nix flake check` builds only the runner's system (x86_64-linux). It evaluates
the aarch64 outputs and says it skipped them, which is enough.

**Fallback,** used only if the VM test fails twice on `main` with no code
cause. Step 4 then becomes `nix flake check -L --no-build`, followed by
`nix build -L` of `checks.x86_64-linux.{shellcheck,cli,manifest,no-hardcoded-colours,module-gating}`.
The `module` VM test is then run by hand before a release. The workflow file
carries this as a comment, not as dead YAML.

### D2: Hardening the reconcile unit (E2)

**Why the client can be locked down.** `bin/nixarchy-flatsnap-reconcile` is
a *client*:

- it runs `snap install`, `refresh`, `remove`, `list` and `wait`, plus jq,
  awk and grep;
- it writes only `$STATE_DIRECTORY/managed`.

The downloads, squashfs mounts, cgroups and the setuid `snap-confine` all
belong to `snapd.service`, a separate unit that this change leaves alone. snapd
authorizes the client by the peer UID on `/run/snapd.socket` (SO_PEERCRED).
So the unit must stay `User=root`, but it needs no capabilities.

These keys are added to `systemd.services.nixarchy-flatsnap-snaps.serviceConfig`
in `module.nix`, after the existing keys. Each comes with why it is safe for
the snapd client.

| Directive | Why the snap client still works |
|---|---|
| `NoNewPrivileges = true` | Only `snap run` executes the setuid `snap-confine`, and the reconciler never runs `snap run`. install, refresh and remove are socket requests. |
| `CapabilityBoundingSet = ""`, `AmbientCapabilities = ""` | Root with no capabilities. snapd checks the UID, not capabilities. The only file the unit writes is in its own `StateDirectory`, which root owns, so it needs no `CAP_DAC_OVERRIDE`. |
| `ProtectSystem = "strict"` | The whole filesystem is read-only except `StateDirectory` (`/var/lib/nixarchy-flatsnap`), which systemd keeps writable. The client does not write to `/var/lib/snapd`; the daemon does. |
| `ProtectHome = true` | `/root` and `/home` are hidden. With no `~/.snap/auth.json`, the client acts anonymously, which is how it already runs, because the store never logs in. |
| `PrivateTmp = true` | The reconciler makes no temporary files. `managed.new` sits in the state directory. |
| `PrivateDevices = true` | The client opens no device node. |
| `ProtectKernelTunables`, `ProtectKernelModules`, `ProtectKernelLogs`, `ProtectControlGroups`, `ProtectClock`, `ProtectHostname` = `true` | The client touches none of these. snapd's own kernel and cgroup work happens in `snapd.service`. |
| `RestrictAddressFamilies = [ "AF_UNIX" ]` | Its only socket is `/run/snapd.socket`. The daemon does all network I/O. |
| `RestrictNamespaces = true` | The client makes no namespaces. snap-confine does, but only under `snap run`, and inside snapd's units. |
| `LockPersonality`, `RestrictRealtime`, `RestrictSUIDSGID` = `true` | Not used by bash, jq, awk or the Go client. |
| `MemoryDenyWriteExecute = true` | No JIT: bash, jq and gawk are C, and the Go snap client does not need W+X memory. |
| `SystemCallArchitectures = "native"`, `SystemCallFilter = [ "@system-service" ]` | The client's calls are ordinary file, socket and process calls, all in `@system-service`. |
| `UMask = "0077"` | `managed` is private to root. |

Anything that has to be relaxed stays in the unit with a comment saying which
operation needed it. `DynamicUser`, and running as a non-root user with polkit,
are rejected; see below.

**Checks.** The VM test (`checks.module`) gets two more assertions:

- `systemd-analyze security nixarchy-flatsnap-snaps.service --threshold=<score>`
  succeeds. Take the score measured after hardening and round it up, so the
  check fails if hardening is later removed.
- Once the unit has run, its journal names `hello-world`, which shows it
  reached snapd over the socket. The journal contains none of
  `Permission denied`, `Read-only file system` or `Operation not permitted`.
  The VM has no network, so the install is expected to fail on the download,
  not on the sandbox.

The real install, refresh and remove is the manual check on razer (see
Verification).

### D3: The flake (E3, E5, E10)

- **`packages.cli`** (`flake.nix:55-59`):
  - Add `gnused`, `gnugrep` and `nix` to `runtimeInputs`, next to curl, jq,
    gawk and coreutils. The CLI calls `sed` in `flake()`, `grep`,
    `nix-instantiate` (:219, :274) and `nix eval` (preflight).
  - `flatpak`, `snap`, `sudo`, `pkexec` and `nixarchy-apply` stay host tools.
    `writeShellApplication` puts `runtimeInputs` in front of `PATH` without
    replacing it, so these are still found.
  - Add `meta` like the plugin's: `description`, `homepage`, `license`,
    `platforms`, and `mainProgram = "nixarchy-flatsnap"`.
- **`formatter`:**
  `formatter = forAll (system: nixpkgs.legacyPackages.${system}.nixfmt);`.
  This task adds the output only. Nothing is reformatted here, so the diff stays
  reviewable and does not conflict with #10 and #13. There is no format check
  in CI yet.
- **The shellcheck check** (`flake.nix:68`) also covers `${./docs/record.sh}`
  and `${./tests/model.sh}`. Both are already clean under the local shellcheck.
- **`checks.plugin-no-symlinks` is deleted** (`flake.nix:102-106`). The plugin
  is made with `runCommand` and plain `cp` of files named one by one, so it
  cannot contain a symlink. The comment at `flake.nix:32-33` already says why.
- **`nixosModules.flatsnap` is dropped** (`flake.nix:22-24`):
  - The compose assertion in `module-gating` (`flake.nix:125-135`) imports
    `./module.nix` directly, next to `nix-snapd.nixosModules.default`. It
    tests the same thing, that the module composes with a host's own
    nix-snapd, without exporting it.
  - The comment at `module.nix:8-12` changes to say that `default` is the only
    output. A host that already imports nix-snapd can import `module.nix` by
    path, or stay on the pin it has today.
- **`module.nix:84`:** delete the stray blank line after
  `config = lib.mkMerge [`.

### D4: The flake path (E4)

Only `flake()` and the start of `cmd_preflight` in `bin/nixarchy-flatsnap`
change. `write_state` (#13) and `cmd_apply` (#10) are not touched.

- **`flake()`** (:374-382) keeps the order it has: `NIXARCHY_FLAKE`, then
  what it reads out of `nixarchy-apply`, then `/etc/nixos`. When it falls back
  to `/etc/nixos` because the sed found nothing, it prints to stderr:
  `nixarchy-flatsnap: could not read the flake path from nixarchy-apply; using /etc/nixos (set NIXARCHY_FLAKE to override)`.
  Stdout stays clean for the panel, which reads only stdout.
- **The dead grep is deleted** (:395-396,
  `grep -q flatsnap "$apply_bin" || die ...`). Every nixarchy since #914 copies
  `flatsnap.nix`, so the check can no longer fail. An older nixarchy that does
  not copy it still fails in preflight, where `hasModule` is false. The comment
  above `cmd_preflight` (:384-390) loses its second bullet.
- **The nixarchy follow-up.** This task does not open it; the PR description
  lists it. nixarchy-apply should expose the flake it rebuilds, for example
  `nixarchy-apply --print-flake`, or a `programs.nixarchy.flake` value written
  to a known file such as `/etc/nixarchy/flake`. Once it exists, `flake()`
  calls it and the sed goes.

### D5: `docs/record.sh` (E6)

The script is a plain bash file with no tests. Its fixes follow the order of
the script:

1. **Header** (:1-16): the usage becomes
   `[--dry-run | --encode-only]`, with `OUT` and `NIXARCHY_SRC` described. The
   outputs are named as they are now: `flatsnap-{flatpak,snap,apply}.gif` and
   the `NN-*.webp` stills. The step-2 reference to plan #5 stays.
2. **Arguments** (:20-24): `"")` does nothing. `*)` dies with the usage and
   runs nothing, so a mistyped option can no longer start a real take.
3. **`OUT`** (:26): the default is `$(mktemp -d -t flatsnap-media.XXXXXX)`,
   which is private and unpredictable, and is printed at the start.
   `--encode-only` requires `OUT` to be set explicitly, because that is where
   the earlier take is.
4. **Pinned nixarchy** (:51): a constant `NIXARCHY_REV=<commit>` sits at the
   top of the script, and the prefetch reads
   `github:olafkfreund/nixarchy/$NIXARCHY_REV`. `NIXARCHY_SRC` still overrides
   it. The rev is nixarchy `main` at the time of the change, and is bumped on
   purpose.
5. **`--dry-run` changes nothing and fetches nothing:**
   - with `DRY=1`, `encode_and_gate` prints the prefetch it would run and
     returns, before `nix flake prefetch`;
   - `mkdir -p "$OUT"` and `: >"$OUT/scenes.tsv"` (:138-139) run only when
     `DRY=0`;
   - `scene()` (:186-191) prints and does not write in a dry run.
6. **`--encode-only` with no live shell:** the block that reads the session's
   handles (:109-113) moves below the `--encode-only` branch. Encoding needs
   ffmpeg, magick and nixarchy's scripts, not Wayland.
7. **Dead variables** (:66-74, :95): delete `flathub`, `remove`, `removed`,
   `d_remove`, and the `: "$…"` lines that only kept shellcheck quiet about
   them.
8. **Cleanup deletes only the take's own generations** (:162-168):
   - `wait_apply` records each new generation it sees (`readlink "$PROFILE"`
     after the change) in an array, `made`;
   - the trap switches back to `START_GEN` as before, and passes
     `--delete-generations` only the numbers in `made`. The `find`, `sed` and
     `awk` scan of every newer generation goes;
   - a generation made by anyone else while the take runs is kept, and the trap
     says so: `newer generations not made by this take were kept: …`.

The `rm -f "$FS_FILE.bak"` at :170 stays for now. #13 (C4) removes the `.bak`
file and that line together.

## Alternatives rejected

- **Cheap checks only, with no KVM.** This leaves out the one check that
  boots the module. KVM runners are free for public repositories. The cheap set
  is kept as the fallback in D1.
- **Self-hosted or Cachix-backed CI.** It needs secrets or a machine to keep
  up, and the intent rules out secrets.
- **`DynamicUser`, or a non-root user with a polkit rule for snapd.** snapd
  lets a non-root client install only through polkit's
  `io.snapcraft.snapd.manage`. That means a new polkit rule, which is more
  surface than it removes, and it would change the unit's contract. Root with
  no capabilities gets most of the benefit.
- **`ProtectSystem = "full"`.** It leaves `/var` and `/etc` writable. `strict`
  plus `StateDirectory` is exact.
- **`IPAddressDeny = "any"`.** It adds nothing once `RestrictAddressFamilies`
  allows only `AF_UNIX`.
- **Changing `flake()` to call a nixarchy interface now.** No such interface
  exists yet. Sed plus a warning is honest until one does.
- **Deleting `record.sh`'s generation scan and leaving generations to the
  user.** A take always makes two. Leaving them clutters the boot menu, which
  the #5 constraints ruled out.
- **Rewriting plans #1 and #5 in place.** Approved text is the audit trail,
  and the intent says amend, not rewrite.
- **Running `nix fmt` over the repo in this task.** It would touch every
  `.nix` file and collide with #10 and #13. That is a separate commit after
  they merge.
- **`devShells`.** The checks already bring every tool in their own
  derivations, and no contributor has asked for a shell. It can be added when
  someone needs it.
- **Deleting a fixture for E9.** Doing so breaks `tests/cli.sh` unless
  `search_flathub` changes; see D6.

## Risks

- **Hardening breaks snap operations that the VM test cannot reach.** The VM
  has no network, so a real install, refresh and remove is never exercised
  under the hardened unit.
  - Most likely: `MemoryDenyWriteExecute` or `SystemCallFilter` against the
    Go client, or `ProtectHome` if the client insists on writing `~/.snap`.
  - Where: every nixarchy host that declares a snap, after nixarchy bumps the
    input.
  - Mitigation: the manual check on razer below, before the PR merges. A
    directive that fails there is dropped with a comment, not guessed at.
- **CI flakiness or runtime.** A VM test on shared runners can be slow or
  flaky. The 45-minute timeout and the documented fallback cover it.
  First-run build time is unknown until the first PR; there is no binary cache
  for this repo.
- **Coordination with #13 and #10 in `bin/nixarchy-flatsnap`.** #13 changes
  `write_state` (around :260-280), and #10 changes `cmd_apply` (:420-446). This
  task edits only `flake()` (:374-382) and the head of `cmd_preflight`
  (:384-396), so the hunks do not overlap. But `cmd_apply` calls
  `cmd_preflight`, and #10 may change how that call handles errors (B2). The
  PR that merges second rebases and re-runs `tests/cli.sh`. `record.sh:170`
  (`.bak`) is left to #13.
- **A host that imports `nixosModules.flatsnap`.** A code search of
  olafkfreund finds none, and nixarchy uses `default`. A private or unpushed
  config would fail to evaluate after its next input update, with a clear
  "attribute missing" error. It would be fixed by importing
  `inputs.nixarchy-flatsnap + "/module.nix"`.
- **Pinning `nix` in `packages.cli`.** A client from this flake's nixpkgs can
  be newer than the host's daemon. The daemon protocol is backwards
  compatible, and the plugin copy (the one the panel runs) still uses the
  host's nix. Only the terminal `cli` package changes.
- **Keeping the duplicate fixture (E9)** goes against the finding as written.
  If the user wants it gone, the fix is one line in `search_flathub`
  (`${2:-flathub-search-$1.json}`), far from #10's and #13's hunks, and then
  `flathub-search.json` can be deleted.
- **`record.sh` changes are only proved by a real take.** They are tested on
  razer and never on p620, with the #5 rules: announce on the agent bus,
  restore the desktop, and post the generation razer is left on.
