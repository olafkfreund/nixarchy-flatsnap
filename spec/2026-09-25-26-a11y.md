# Spec: the menu's rows, card and confirmations reach a screen reader

Line numbers are for `main` at d3a2744, which is what the intent was read
from. The intent says c14fdd7; that label is wrong, the lines are right.

## Decisions carried from the intent review

- D1. The first verification step is a probe of the AT-SPI tree on razer
  with the menu open, and Orca. If the tree is empty, the properties still
  land, the Quickshell gap is listed as a follow-up (not opened here), and
  the PR says the change is unverified at runtime.
- D2. Fixed here, in flatsnap, with the `ListItem` shape already used by
  `olafkfreund.govee/GoveeMenu.qml:233-236` and
  `nixarchy.herdr/Card.qml:248-250`. One follow-up issue copies it to the
  sibling plugins after the razer check.
- D3. The armed state is conveyed by an announcement plus the prompt's
  existing text. No visual change.
- D4. The card's accessible name is the app and its store; its description
  is the trust summary.

## Design

The runtime is Qt 6.11.2 (quickshell 0.3.1's `qtdeclarative`), which has
`Accessible.announce(message, politeness)` (Qt 6.8+; the symbol
`QQuickAccessibleAttached::announce` is in its `libQt6Quick.so.6`). A
Qt Quick `Text` already exposes role `StaticText` with its text as its
name, so the `Line`s on the card and in the footer need nothing new to be
read.

### 1. One armed flag, in the model

`FlatsnapModel.qml` gains one read-only property:

```qml
readonly property bool armed: pendingDelete !== "" || applyArmed || classicArmed || queueArmed
```

It replaces the two copies of that expression that exist today:
`FlatsnapModel.qml:319` (`cancelsConfirm`) becomes `if (!armed) return false`,
and the message line's colour at `Menu.qml:395` becomes
`fs.armed ? Color.urgent : Color.menu.text`. The colour is unchanged.

### 2. The list and its rows (`Menu.qml:324-357`)

On the `ListView` (`list`):

```qml
Accessible.role: Accessible.List
Accessible.name: fs.tab === 0 ? "Add" : "Declared"
```

On the row delegate `Rectangle`:

```qml
Accessible.role: Accessible.ListItem
Accessible.name: rowText.text
Accessible.selected: index === fs.cursor
```

The name is the row's own text, so it includes the "← y removes it and its
data" suffix while a delete is pending. There is no `onPressAction`: the
menu is keyboard only and an AT press would be a new input path.

The keyboard stays on the `keys` FocusScope (`Menu.qml:126`), so moving
the cursor changes which row is `selected` but moves no focus. Whether
Orca speaks a `selected` change without a focus change is part of the
probe (Verification P3). If it does not, the row under the cursor is
announced when the cursor moves:

```qml
Connections {
  target: fs
  function onCursorChanged() {
    var row = list.visible ? list.itemAtIndex(fs.cursor) : null
    if (row) root.announce(list, row.Accessible.name, false)
  }
}
```

`itemAtIndex(fs.cursor)` rather than `currentItem`, because `currentIndex`
is a binding on `fs.cursor` and may not have updated yet when this runs.

This conditional step is taken only on the probe's result, so there is
never both a focus report and an announcement for the same move.

### 3. The card (`Menu.qml:239-318`)

On `cardCol`:

```qml
Accessible.role: Accessible.Grouping
Accessible.name: (c.name || c.id || "") + ", " + (isSnap ? "Snap" : "Flatpak")
Accessible.description: trustSummary
readonly property string trustSummary: {
  var v = c.verified
  var s = v === true ? "publisher verified" : v === false ? "publisher not verified" : "publisher verification unknown"
  if (!isSnap && c.permissions === null) s += ", permissions unknown"
  if (isSnap && fs.classic) s += ", classic confinement, runs without a sandbox"
  return s
}
```

"permissions unknown" is included because it is the other card line that
is urgent by colour today (`Menu.qml:266`). The card is announced when it
opens, since the focus does not move to it: the existing
`Connections { onCardChanged }` (`Menu.qml:237`) gains
`if (fs.card) root.announce(cardCol, cardCol.Accessible.name + ". " + cardCol.trustSummary, false)`.

The card's `Line`s are untouched: each is already a `StaticText` with its
text as its name, in reading order.

### 4. The message line (`Menu.qml:391-396`)

The footer's message `Line` gets `id: messageLine` and:

```qml
Accessible.description: fs.armed ? "confirmation pending" : ""
```

so a screen reader that reads the line later can tell a prompt from a
status without the colour. Every new non-empty message is announced;
an armed one interrupts:

```qml
Connections {
  target: fs
  function onMessageChanged() { if (fs.message.length > 0) root.announce(messageLine, fs.message, fs.armed) }
}
```

Every arming path sets its flag before its message
(`FlatsnapModel.qml:177`, `:207-208`, `:219-221`, `:257-258`, `:301-302`),
so `fs.armed` is already true when `messageChanged` fires. A scroll key
that keeps the arm keeps the message (`tests/model.qml:115`), so it is not
announced twice.

### 5. One helper

```qml
// Assertive interrupts the screen reader; kept for a pending confirmation.
function announce(item, text, urgent) {
  if (text.length === 0 || typeof item.Accessible.announce !== "function") return
  item.Accessible.announce(text, urgent ? Accessible.Assertive : Accessible.Polite)
}
```

The `typeof` check keeps a Qt older than 6.8 from throwing: the menu then
works as today, without announcements.

### What does not change

No colour, size, layout, key or text changes. `Line` keeps
`textFormat: Text.PlainText`; accessible names and announcements are the
same plain strings, never markup. The key-hint line and the build log get
nothing new.

## Alternatives rejected

- **The armed OR in `Menu.qml` only.** No model change and no test, but it
  leaves a third copy of the expression next to the one in
  `cancelsConfirm`. One property used by both is less code.
- **A visible marker on an armed prompt** (a prefix or symbol). The prompts
  already say "again", "WITHOUT a sandbox", "y removes"; D3 decided no
  visual change.
- **Moving keyboard focus onto the current row** so Orca reports it as a
  focus change. It would move the keys away from the FocusScope that
  handles every key, and change keyboard behaviour for everyone.
- **`Accessible.onPressAction` on rows**, as govee has. It adds an input
  path the keyboard-only menu does not have.
- **Announcing the card's every line on open.** Long permission lists would
  make it a monologue. The name and trust summary are announced; the rest
  is read on demand.
- **A shared component across the sibling plugins now** (D2). Wait until
  razer shows the pattern works.
- **Waiting for omarchy-shell `qs.Ui` to grow accessibility.** It sets
  none today, and #26 would be blocked on another project.

## Risks

- **Nothing may be readable at all.** On p620, quickshell registers on the
  AT-SPI bus with zero children even while the bar is shown. If razer shows
  the same with the menu open, every property here is correct but unheard
  (D1).
- **Chatter.** Status messages ("checking…", "found in more than one
  place") are announced politely. If Orca makes that noisy in practice, the
  fallback is to announce only armed prompts; the probe decides.
- **Double speech** if Orca both reports a `selected` change and hears the
  cursor announcement; that is why §2's announcement is conditional.
- **Merge order #36 → #28 → #27 → #26; this lands last.** #36 (footer
  glitches) rewrites the footer that holds the message line
  (`Menu.qml:387-402`) and may touch `fs.message`; #28 (Bus Policy
  overrides) and #27 (manifest permission highlight) touch the overrides
  path and the card's permission line. Expect conflicts in `Menu.qml` and
  in `FlatsnapModel.qml` around `queue()` and `cancelsConfirm`, and
  re-read every line number here after rebasing. If #27 adds new urgent
  card lines, the trust summary in §3 must name them.
- **Older Qt on another host.** Guarded by the `typeof` check in §5; the
  roles and names work on any Qt 6.
- Only razer may run the menu for these checks; nothing is applied on p620.

## Verification

In this order; P1 comes before anything else.

- **P1. Razer probe, before the change** (D1). On razer, with the flatsnap
  menu open on the Add tab: list the apps on the AT-SPI bus
  (`org.a11y.Bus.GetAddress`, then `GetChildren` on
  `org.a11y.atspi.Registry` `/org/a11y/atspi/accessible/root`) and walk
  quickshell's children, or use Accerciser or the ai-mirror `a11y_tree`
  tool. Record whether the `nixarchy-flatsnap-menu` window and its items
  appear. If the tree is empty: land §1-§5 anyway, add a "file with
  Quickshell: layer-shell windows expose no AT-SPI children" follow-up to
  the PR, and say in the PR that the change is unverified at runtime.
- **P2. Razer, after the change, tree present.** Walk the tree again: the
  list has role list and name "Add" or "Declared"; each row has role list
  item, the row's text as name, and exactly one row is `selected`; the
  card is a grouping named "<app>, Flatpak|Snap" with the trust summary as
  description.
- **P3. Orca on razer.** With Orca running: open a card (its name and
  trust summary are spoken); press `x` on a snap card (the classic prompt
  interrupts); press Enter with an override (the override prompt is
  spoken); on Declared press `d` (the delete prompt is spoken); press `a`
  (the apply summary is spoken). Move with `j`/`k`: record whether the row
  is spoken. If not, take the conditional step in §2 and repeat.
- **T1. `tests/model.sh`** (runs `tests/model.qml` against the model): new
  cases that `fs.armed` is false at rest and true for each of
  `pendingDelete`, `applyArmed`, `classicArmed` and `queueArmed`, false
  again after `disarm()`, and that the existing `cancelsConfirm` cases
  still pass.
- **T2. `nix flake check`**: shellcheck, cli, manifest,
  `no-hardcoded-colours`, `no-text-multiplier`, module checks, all green.
- **T3. No visual change.** On razer at scale 1, a screenshot of the Add
  list, a snap card with `x` armed, and the Declared list with `d` armed
  match the same shots from `main`.
- **T4. No QML warnings.** Opening the menu on razer logs no new quickshell
  warning (journal), in particular no `TypeError` from `announce`.
