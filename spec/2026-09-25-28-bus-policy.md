# Spec: let the panel's overrides field take a Bus Policy override

## Decisions carried from the intent

| # | Question | Decision |
|---|---|---|
| Q1 | Separator | Keep whitespace. Tokenise by a left-to-right match of whole overrides against the same shape as `OV_RE` |
| Q2 | Existing input | Every input that works today tokenises the same |
| Q3 | Text that does not parse | The first Enter says so, names the part that does not parse, and does not arm. The CLI still validates |

Also required: a Bus Policy override on the escape list gets the red
ESCAPES wording and the second Enter, as the Context rows do.

Line numbers are for `origin/main` at d3a2744.

## Design

### D1: tokenise whole overrides (`FlatsnapModel.qml`)

A new function in the model replaces the split at `FlatsnapModel.qml:214`:

```js
// One override, with the CLI's grammar (OV_SEC, OV_KEY, OV_VAL in
// bin/nixarchy-flatsnap:20-23), taken from the front of the text. Keys and
// values have no spaces, so whitespace inside an override is only ever in
// its section, and the value ends at the next whitespace.
readonly property var _ovHead:
  /^\s*([A-Za-z][A-Za-z ]{0,40}\.[A-Za-z0-9_.-]{1,100}=[A-Za-z0-9_.\/:~!@+=-]{1,200})(?=\s|$)/

// {ov: [override, ...], bad: "" or the text from the first part that
// does not parse to the end}
function _splitOverrides(text) {
  var s = String(text).trim(), ov = [], at = 0, m
  while (at < s.length && (m = _ovHead.exec(s.slice(at)))) { ov.push(m[1]); at += m[0].length }
  return { ov: ov, bad: s.slice(at).trim() }
}
```

The character classes are copied from `OV_SEC`, `OV_KEY` and `OV_VAL`,
with the same bounds. The only difference is `/` escaped for the JS
literal. There is no `y` (sticky) flag. The regex is anchored and matched
against the remaining slice, so it does not depend on the QML engine
supporting ES2015 sticky regexes.

Why it matches the CLI:
- A section is letters and spaces, so it ends at the first `.`. A key has
  no `=`, so it ends at the first `=`. A value has no whitespace, so it
  ends at the next whitespace or the end of the text. At each step there
  is only one way to match, so the regex never backtracks into a
  different split.
- `(?=\s|$)` makes an override end where the text ends or at whitespace.
  A value longer than 200 characters, or one containing a character
  outside `OV_VAL` (such as `$`), fails the match. Such text is then left
  in `bad`, and is not cut into a shorter override.
- Q2 holds. If an input works today, every whitespace-separated token
  matches `OV_RE`, so its section has no spaces. From the token's first
  character, the regex takes the same section, key and value, and stops
  at the same whitespace. The tokens are therefore identical.

Checked with node against these inputs (the result is what `add` receives
as separate `--override` arguments):

| Input | `ov` | `bad` |
|---|---|---|
| `Context.filesystems=xdg-pictures:ro  Environment.LC_ALL=C.UTF-8` (placeholder, `Menu.qml:282`) | `Context.filesystems=xdg-pictures:ro`, `Environment.LC_ALL=C.UTF-8` | `""` |
| `Session Bus Policy.org.freedesktop.Flatpak=talk` | that one string | `""` |
| `System Bus Policy.org.freedesktop.login1=own` | that one string | `""` |
| `Context.filesystems=home Session Bus Policy.org.freedesktop.Flatpak=talk Context.sockets=ssh-auth` | the three overrides | `""` |
| `Context.filesystems=~/Games<TAB>Environment.A=b=c` | `Context.filesystems=~/Games`, `Environment.A=b=c` | `""` |
| `Context.filesystems=xdg-pictures:ro bad` | `Context.filesystems=xdg-pictures:ro` | `bad` |
| `Context.filesystems=home Context.bad` | `Context.filesystems=home` | `Context.bad` |
| `Context.filesystems=$(id)` | none | `Context.filesystems=$(id)` |
| `` or spaces only | none | `""` |

`bash`'s `[[ $x =~ $OV_RE ]]` splits the two Bus Policy strings the same way.
The section is `Session Bus Policy` or `System Bus Policy`, the key is
`org.freedesktop.Flatpak` or `org.freedesktop.login1`, and the value is
`talk` or `own`. So `cmd_add` (`bin/nixarchy-flatsnap:452`) accepts each
token.

### D2: `queue()` uses it (`FlatsnapModel.qml:213-226`)

- `var r = _splitOverrides(overrides)`.
- If `r.bad !== ""`, set `message` to
  `"Not an override: " + r.bad + " (Section.key=value, separated by spaces)"`
  and return. Do not arm, and do not write. The message is in the urgent
  colour only while something is armed (`Menu.qml`, footer), so it shows in
  the ordinary colour. That is acceptable: nothing is pending. If `r.bad`
  is longer than 60 characters, it is cut there and "…" is added, so the
  footer stays short.
- Otherwise use `r.ov` exactly where `ov` is used today: arming, the
  `_escapes` map, and one `args.push("--override", …)` per element. The argv
  array stays as it is, and no string is handed to a shell.
- The ordinary first-Enter message joins overrides with `", "` instead of
  `"  "` (`FlatsnapModel.qml:223`). No override can contain a comma, so
  with sections that have spaces the user can see where each override
  starts and ends. The ESCAPES message already joins with `"; "`.

`_escapes()` (`FlatsnapModel.qml:236-248`) is unchanged. Its regex already
allows spaces in the section. `Session Bus Policy.org.freedesktop.Flatpak=talk`
matches the `ESCAPES_JSON` row at `bin/nixarchy-flatsnap:38`, and
`System Bus Policy.<any>=talk|own` matches row `:39` through key `"*"`. So
both get the red ESCAPES wording and the second Enter with no change there.

### D3: nothing else in the panel or CLI

- `bin/nixarchy-flatsnap` is not changed. `OV_*`, `cmd_add`, `check_entries`
  and `ESCAPES_JSON` stay as they are.
- The `Menu.qml` placeholder (`:282`) stays. It is still true.
- The Declared list is not changed. It never renders overrides
  (`Menu.qml:342-354`).

### D4: docs

- `README.md:191-193`: remove the "cannot be typed into the panel" note.
- `README.md:56` (keys table, `p`): add "several separated by spaces; a

  the cases below.

## Alternatives rejected

- **`;` as the separator.** It is unambiguous, but it adds new syntax,
  makes the placeholder and README wrong, and needs a fallback for today's
  space-separated input anyway (Q2).
- **Newline with a multi-line field.** Enter in the field is already the
  first queue press (`Menu.qml:179-181`), so a newline would need another
  key.
- **Split on whitespace followed by `Section.key=`** (the lookahead in the
  issue). It also matches before `Bus` and `Policy` inside the section, so
  `Session Bus Policy.…` still falls apart.
- **Recognise known section names.** That is a second copy of nix-flatpak's
  section list. It would go stale, and it is stricter than the CLI.
- **Have the CLI tell the panel its grammar** (for example, the regex on
  each card, like `sandboxEscapes`). That keeps one source, but it is more
  moving parts for three character classes that have not changed since #1.
  `_escapes()` already repeats `OV_SEC` and `OV_KEY`. The model tests pin
  the panel side and the CLI tests pin the CLI side.

## Risks

- **A stray word joins the next section.** In `foo Context.x=y`, `foo
  Context` is a valid `OV_SEC`. It is taken as one override with section
  `foo Context`, and the CLI accepts it: the same grammar, so the same
  result as `--override "foo Context.x=y"` on the command line. Today this
  input fails on the second Enter. Mitigation: the first Enter lists the
  overrides joined by `", "` (D2), so `foo Context.x=y` shows up as one
  item before anything is written. Nothing escapes the sandbox this way:
  nix-flatpak writes an unknown section, and flatpak ignores it. Rejecting
  it would mean the known-section list rejected above.
- **The panel's regex drifts from `OV_*`.** If the CLI grammar changes and
  the panel does not follow, the panel either refuses on the first Enter
  (stricter) or the CLI refuses on the second (looser). Neither writes bad
  state. A comment at both places names the other.
- **The QML engine's regex support.** The regex needs no sticky flag and
  no lookbehind. `(?=…)` lookahead is ES3, so V4 supports it.
- **Merge order #36 → #28 → #27 → #26. This is second.** #36 (footers) will
  touch `Menu.qml` footer and hint lines, and maybe `FlatsnapModel.qml`
  `keysHint`. #28 changes `queue()`, its messages, `tests/model.qml` and
  the README Overrides section. #27 (manifest escapes) reads the same
  `ESCAPES_JSON` and will edit the same README section and `_escapes`
  area. #26 (a11y) touches `Menu.qml` delegates. Rebase on #36 before
  opening the PR. #27 then rebases on this, and inherits the Bus Policy
  model cases instead of re-adding them.
- **Hosts.** This is a panel logic change only. The model tests run under
  `tests/model.sh`, and the live check is on razer. Nothing runs on p620.

## Verification

- **`tests/model.qml`**, new cases on a flatpak card that has the
  `sandboxEscapes` list:
  - Placeholder text `Context.filesystems=xdg-pictures:ro  Environment.LC_ALL=C.UTF-8`:
    arms on the first Enter. On the second, argv has exactly two
    `--override` elements, equal to the two strings.
  - `Session Bus Policy.org.freedesktop.Flatpak=talk`, and `=own`: arms, the
    message contains `ESCAPES` and the override, and it does not write.
    The second Enter's argv has it as one element.
  - `System Bus Policy.org.freedesktop.login1=own`: named as an escape.
  - `System Bus Policy.org.example.Foo=see`: ordinary prompt, no `ESCAPES`
    (the value is not `talk` or `own`).
  - Mixed `Context.filesystems=xdg-pictures:ro Session Bus Policy.org.freedesktop.Flatpak=talk`:
    ESCAPES names the Bus Policy one. On the second Enter, argv has both as
    separate elements.
  - Garbage `Context.filesystems=xdg-pictures:ro bad`, `bad` and
    `Context.filesystems=$(id)`: the first Enter does not arm, does not set
    `busy`, and its message contains `Not an override` and the unparsed
    part.
  - All existing override cases (`tests/model.qml:84-190`) pass unchanged.
  - Run with `bash tests/model.sh` on razer or a local Wayland session.
- **`tests/cli.sh`**, a new check after "add flatpak with overrides":
  `run add flatpak org.gnome.Calculator --override "Session Bus Policy.org.freedesktop.Flatpak=talk" --override "System Bus Policy.org.freedesktop.login1=own"`
  gives `.[0].overrides == {"Session Bus Policy":{"org.freedesktop.Flatpak":"talk"},"System Bus Policy":{"org.freedesktop.login1":"own"}}`,
  then `parses`. A following `run list` shows the same object, which is
  the round trip through the generated `.nix` file.
- **`nix flake check`** passes: shellcheck, cli, module, and the
  no-text-multiplier check.
- **Manual on razer:** type the Session Bus Policy override into the field,
  press Enter, and see the red ESCAPES line. Press Enter again. Then
  `nixarchy-flatsnap list` shows the section with spaces.
