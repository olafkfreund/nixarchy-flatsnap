# Spec: install Flatpak and Snap apps from the Omarchy menu

## Decisions carried from the intent

| # | Question | Decision |
|---|---|---|
| Q1 | Snap service | `nix-community/nix-snapd`, pinned flake input of this repo |
| Q2 | Declarative Snaps | this repo ships a reconciler; no imperative-only tracking |
| Q3 | Where lists live | generated `~/.config/nixarchy/flatsnap.nix` |
| Q4 | Entry point | Omarchy menu row *Install → Flatpak & Snap*; no new chord in v1 |
| Q5 | Flatpak scope | system-wide only |

## Design

Four parts. Three are in this repo, and one is a small patch to nixarchy.

```
Omarchy menu ─ Install → Flatpak & Snap ─► nixarchy-plugin nixarchy.flatsnap
                                              │ (QML panel, keyboard)
                                              ▼ argv only, JSON out
                                   bin/nixarchy-flatsnap (bash CLI)
                                   ├─ resolve / search  → Flathub + Snap Store APIs
                                   ├─ add / rm / list   → ~/.config/nixarchy/flatsnap.nix
                                   └─ apply             → nixarchy-apply (existing)
                                              ▼ copies flatsnap.nix into the flake
                          nixosModules.default (this repo)
                          ├─ services.flatpak.packages / overrides   (nix-flatpak, already in nixarchy)
                          └─ services.snap + nixarchy-flatsnap-snaps.service (nix-snapd + reconciler)
```

### D1: CLI `bin/nixarchy-flatsnap`

This is a single bash script, following the same pattern as `nixarchy-pkg/bin/nixarchy-pkg`. The QML side only ever
spawns it with an argv array and reads JSON from stdout. All logic lives here, where
it can be tested without a shell session.

| verb | does |
|---|---|
| `resolve <text>` | Classifies the pasted text and returns `{store, id, name, summary, publisher, license, permissions, confinement, channels}` |
| `search <store> <query>` | Flathub `POST /api/v2/search` or Snap `GET /v2/snaps/find`; returns up to 20 hits |
| `list` | Declared entries from `flatsnap.nix` (read with `nix-instantiate --eval --json`), marked installed or not from `flatpak list --app --columns=application` / `snap list` |
| `add flatpak <appId> [--override k=v…]` | Appends the entry to the file |
| `add snap <name> [--channel c] [--classic]` | Appends the entry to the file |
| `rm <store> <id>` | Removes the entry from the file |
| `apply` | `NH_ELEVATION_STRATEGY=pkexec nixarchy-apply --yes --no-preview`, streamed as JSON lines, as in `nixarchy-pkg:1187-1230` |

**Input classification (`resolve`):**

| input | store | id |
|---|---|---|
| `https://flathub.org/apps/<id>` (optionally `/details/`) | flatpak | `<id>` |
| `https://dl.flathub.org/repo/appstream/<id>.flatpakref` | flatpak | `<id>` (from Flathub, so no remote or hash needed) |
| `https://snapcraft.io/<name>` | snap | `<name>` |
| `flatpak install [flathub] <id>` / `snap install <name> [--classic] [--channel=c]` | as written | as written; the flags are kept |
| reverse-DNS with ≥ 2 dots, e.g. `com.spotify.Client` | flatpak | as is |
| `^[a-z0-9][a-z0-9-]{0,39}$` | ask: both stores are looked up, and the user picks one | as is |
| anything else, any `http://`, any other host, a `.flatpakref` from a non-Flathub remote | refused with a one-line reason | none |

The IDs are validated against these grammars before they go anywhere else:
- Flatpak: `^[A-Za-z_][A-Za-z0-9_-]*(\.[A-Za-z_][A-Za-z0-9_-]*){2,}$`
- Snap: `^[a-z0-9][a-z0-9-]{0,39}$`

Only a validated ID reaches `curl`, the Nix file, or a process argument. curl
runs with `--proto =https --max-time 10 --max-filesize 2M`. The metadata comes
from `GET flathub.org/api/v2/summary/<id>` (the permissions are in
`.metadata.permissions`) plus `/appstream/<id>`, or from
`GET api.snapcraft.io/v2/snaps/info/<name>` with `Snap-Device-Series: 16`.
All four endpoints were probed live on 2026-09-23.

**Writing the file:** the CLI owns `flatsnap.nix` completely. It regenerates the
whole file from the entry list, so it never edits it in place. It follows the nixarchy
idiom: back up the file, write it, run `nix-instantiate --parse`, and restore the backup on failure. Values
are emitted as Nix strings with `\`, `"` and `${` escaped. The ID grammars already exclude
all three, so the escaping is a second line of defence.

```nix
# Generated by nixarchy-flatsnap. Edit through the menu, or by hand and keep the shape.
{
  programs.nixarchy.flatsnap = {
    flatpaks = [
      { appId = "com.spotify.Client"; }
      { appId = "org.gimp.GIMP"; overrides = { Context.filesystems = [ "xdg-pictures" ]; }; }
    ];
    snaps = [
      { name = "spotify"; channel = "stable"; classic = false; }
    ];
  };
}
```

### D2: NixOS module `nixosModules.default`

- `imports = [ inputs.nix-snapd.nixosModules.default ]`.
- `options.programs.nixarchy.flatsnap.flatpaks` is a list of
  `{ appId; overrides ? {}; }`. `snaps` is a list of
  `{ name; channel ? "stable"; classic ? false; }`. Both are type-checked, and
  the ID grammars from D1 are enforced again with `lib.types.strMatching`.
- **Flatpaks:** when the list is non-empty, the module sets `services.flatpak.enable = true`
  and `services.flatpak.packages = map (f: { inherit (f) appId; origin = "flathub"; }) cfg.flatpaks`.
  `packages` is a list option, so this *merges* with what nixarchy's curated
  `modules/flatpaks.nix` sets, and does not replace it.
  `services.flatpak.overrides.<appId>` is set only for entries that have overrides.
  **The module never sets `remotes`.** The curated module, or nix-flatpak's own
  default, already provides Flathub. Setting `remotes` here is the exact bug the
  `++` comment in `modules/flatpaks.nix` warns about.
- **Snaps:** when the list is non-empty, the module sets `services.snap.enable = true` and adds a
  `nixarchy-flatsnap-snaps.service` unit. It is a `Type=oneshot` unit with
  `After=snapd.service network-online.target` and
  `Wants=network-online.target`, and it is wanted by `multi-user.target`. It is restarted
  whenever its declared list changes (`restartTriggers`). The unit reads a
  JSON list from the Nix store and reconciles it against the installed snaps:
  - it runs `snap install <name> --channel=<c> [--classic]` for each declared snap that is missing;
  - it runs `snap refresh <name> --channel=<c>` when the tracked channel differs;
  - it runs `snap remove <name>` **only** for names in
    `/var/lib/nixarchy-flatsnap/managed`, which is the list of snaps this unit installed, that are no
    longer declared. A snap the user installed by hand is never removed. This is
    the Snap equivalent of `flatpaks.uninstallUnmanaged = false`.
  - A failure for one snap is logged and the unit moves on to the next. The unit exits
    non-zero when any snap failed, so `systemctl --failed` shows it.

### D3: Plugin `nixarchy.flatsnap` (QML)

The plugin has `manifest.json` with `kinds: ["menu"]` and `Menu.qml`, and is built as a
plain directory without symlinks, the same way nixarchy-pkg is built. It is a full-screen card over the focused
monitor that takes the Omarchy theme tokens (`Color.menu.*`, `Style`).

| key | action |
|---|---|
| (typing) / `Ctrl+V` | paste into the field |
| `Enter` | resolve the input; on a result card, queue it |
| `Ctrl+F` / `Ctrl+S` | search Flathub / the Snap Store with the field's text |
| `j`/`k`, `↓`/`↑` | move through the results or the declared list |
| `c` | cycle the snap channel: stable → candidate → beta → edge |
| `x` | toggle classic confinement; confirming needs a second `x` |
| `p` | edit Flatpak overrides (one `key=value` per line) |
| `Tab` | switch between *Add* and *Declared* |
| `d` | un-declare the selected app, after a `y/n` confirmation |
| `a` | apply, with the log streamed into the card |
| `Esc` | back, then close |

The result card shows name, summary, publisher, license and the requested
permissions (Flatpak) or confinement (Snap), all as `Text.PlainText`. It shows
three warnings:
- **Classic:** "Classic snaps run without a sandbox."
- **Every snap:** "Snap confinement on NixOS is weaker than on Ubuntu (no
  AppArmor)."
- **`uninstallUnmanaged` on:** before apply, it lists the Flatpaks that apply will remove.

### D4: nixarchy patch (separate PR on `olafkfreund/nixarchy`)

1. `nixarchy-apply`: change `for part in apps services advanced` to
   `apps services advanced flatsnap`. The loop already skips files that do not exist.
2. `modules/apps.nix`: add a menu row modelled on `install.packages`:
   `"install.flatsnap" = { icon = "󰏗"; label = "Flatpak & Snap"; action = "nixarchy-plugin nixarchy.flatsnap"; when = "nixarchy-plugin --enabled nixarchy.flatsnap"; }`.
   The `when` guard hides the row until the plugin is enabled.

Users wire the module into their own flake, in the same way as
`nixarchy-plugin-browser`:

```nix
inputs.nixarchy-flatsnap.url = "github:olafkfreund/nixarchy-flatsnap";
# NixOS:        imports = [ inputs.nixarchy-flatsnap.nixosModules.default ];
# Home Manager: programs.nixarchy.plugins.flatsnap.src = inputs.nixarchy-flatsnap.packages.${sys}.default;
#               home.packages = [ inputs.nixarchy-flatsnap.packages.${sys}.cli ];
```

### D5: Repository and GitHub Pages

The flake outputs are `packages.<sys>.{default,cli}`, `nixosModules.default` and
`checks.<sys>.*`. The repo also has a `docs/` Jekyll site, deployed by GitHub Pages from `main:/docs`. It copies
`nixarchy/docs/{_config.yml,_layouts,_includes,assets}` so it looks the same
as `olafkfreund.github.io/nixarchy`, and has one `index.md` covering what the plugin is, a screenshot,
install instructions, keys, and the security notes.

## Alternatives rejected

- **Writing our own snapd module.** It would mean owning `/snap`, the snapd units, the setuid
  `snap-confine` and all their breakage. nix-snapd is maintained under nix-community
  (last push 2026-09-20).
- **Imperative `flatpak install` / `snap install` run from the panel.** This contradicts the
  approved intent, and with `uninstallUnmanaged` the app is gone at the next rebuild.
- **Entries in `advanced.nix`.** Generated state would mix with hand-written
  options, and regenerating the file safely would be impossible. (Approved in Q3.)
- **Bundling nix-snapd into nixarchy itself.** That is a bigger change to a repo this
  plugin does not own. It can come later if the plugin proves out.
- **Adding non-Flathub Flatpak remotes in v1.** This needs `remotes` handling that
  preserves Flathub under module merging. It is refused in v1 with a clear
  message, and can be added when someone needs it.
- **Doing the logic in QML `XMLHttpRequest`s.** That logic cannot be tested outside the shell,
  and it would be the second place where input validation happens.
- **Adding a dedicated keybinding.** Rejected in Q4, and every `SUPER+ALT` letter is getting
  scarce anyway (`pkgs/omarchy/default.nix:2012-2021`).

## Risks

| Risk | Where | Mitigation |
|---|---|---|
| nix-snapd's weakened confinement (setuid `snap-confine`, bubblewrap patched to drop `NO_NEW_PRIVS`, no AppArmor) | every host with a snap declared | `services.snap` is enabled only when the snap list is non-empty; the card warns; the README and the Pages site say so plainly |
| `flatsnap.nix` is present but the module is not imported, so evaluation fails with "option does not exist" | a user who installs the plugin but skips the module | `nixarchy-flatsnap apply` checks with `nix eval` for the option before it calls apply, and says exactly which line to add |
| The reconciler runs at boot while offline | laptops | `network-online.target`; failures don't block boot; it retries on the next activation |
| Store API shape changes | everyone | `resolve` fails closed and shows the message "lookup failed: <reason>"; the user can still queue a known-valid ID |
| `uninstallUnmanaged = true` removes Flatpaks that were installed by hand | machines that opt in | the diff is shown before apply (D3) |
| Two writers editing `flatsnap.nix` (the panel plus a hand edit) | rare | the file is regenerated from `list`, which reads the current file first, so hand-added entries that keep the same shape survive |

## Verification

1. `nix flake check` is green. It includes:
   - `checks.cli`: a bats-free shell test (`tests/cli.sh`) covering `resolve`
     classification for every row of the D1 table (with the network stubbed
     via `NIXARCHY_FLATSNAP_OFFLINE=1` fixtures), refusal of hostile inputs
     (`$(…)`, `"; rm`, `${…}`, `http://`, foreign hosts), and `add`/`rm`
     round-tripping through `nix-instantiate --parse`.
   - `checks.module`: a NixOS VM test that declares one Flatpak and one Snap and asserts
     three things: `services.flatpak.packages` holds the Flatpak alongside a curated
     entry and Flathub is still in `remotes`, `snapd.service` is active, and the
     reconciler unit exists. The network-dependent install itself is not
     tested in CI.
   - `checks.plugin`: `omarchy plugin validate` passes on the built plugin
     folder.
2. Manual test on a nixarchy host:
   1. From *Install → Flatpak & Snap*, paste `https://flathub.org/apps/org.gnome.Calculator`.
   2. Queue it, then apply. The app then launches from the Omarchy launcher.
   3. Paste `snap install hello-world`, queue it, apply, and check that `hello-world` runs.
   4. Un-declare both apps and apply. Both are gone. A snap installed by hand beforehand
      is still there.
3. The GitHub Pages site builds and loads at
   `https://olafkfreund.github.io/nixarchy-flatsnap/` with the nixarchy look.
4. `nixarchy-apply` with no `flatsnap.nix` present behaves exactly as it does today.
