# Intent: menu text follows the desktop's scale

## Problem

The menu's window follows the desktop: it opens on the focused monitor and
takes its size from that monitor and from the shell's spacing scale
(`Menu.qml:25-31`, `:59`, `:72-75`). The text inside it does not.

Every line of text goes through `px()`, which multiplies the shell's font
size by a fixed 1.45 (`Menu.qml:22-23`, used at `:52` and `:189`). The
shell's font sizes (`Style.font.caption`, `Style.font.subtitle`) already
follow the desktop's font scale, so the text is scaled twice. On a HiDPI
monitor, or with the shell's font size raised, the menu text is 45% larger
than the rest of the shell and grows faster than the window around it. The
user's requirement is that "the text and the windows needs to follow the
desktop size and scale".

The same 1.45 constant is in four sibling plugins: `nixarchy.pkg`
(`Menu.qml:35`), `nixarchy.devenv` (`Menu.qml:32`), `nixarchy.distrobox`
(`Menu.qml:30`) and `nixarchy-plugin-browser` (`Menu.qml:27`, as `uiScale`).
It is a convention across the plugin family, not a one-off here.

## Proposed outcome

- Menu text size comes from the desktop's scale only. Changing the shell's
  font scale or moving to a monitor with a different scale changes the text
  by the same factor as the window and the rest of the shell.
- At the default scale on a typical monitor, the menu still reads at a
  comfortable size, not smaller than it does today by surprise.
- Text still fits the card and the list rows at every scale: no clipping, no
  overlap.

## Affected users and systems

- Everyone using the flatsnap menu, most visibly on HiDPI monitors or with a
  raised shell font scale.
- `Menu.qml` in this repo.
- If fixed family-wide: the four sibling plugin repos listed above, and
  possibly the shell's shared `Style` tokens.

## Constraints

- Sizes come from the shell's `Style` tokens, not new hardcoded numbers.
- Window sizing already follows the monitor and must keep doing so.
- No behaviour change beyond size: keys, colours and layout stay as they are.
- Verified on the test host (razer), at more than one scale.

## Open questions

1. **Scope.** Fix only this plugin's `Menu.qml`, or agree a shared approach
   (for example one `Style` token for "menu text") across `nixarchy-pkg`,
   `nixarchy-devenv`, `nixarchy-distrobox` and `nixarchy-plugin-browser`?
   The shared route is cross-repo work and needs its own issues there.
2. **Deliberately larger?** Should the menu still be larger than the rest of
   the shell, as the 1.45 suggests someone wanted? If yes, by a scale-aware
   step (a bigger `Style.font` token) rather than a flat multiplier on top.
