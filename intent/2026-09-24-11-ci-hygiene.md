# Intent: CI, a hardened root unit, a safe recorder, and plans that match the code

## Problem

The plugin ships as part of nixarchy, but the repository around it has no
safety net. Its one root service runs with root's full reach, the media
script can break the machine it runs on, and the plans no longer describe
what was built. Line numbers are for `main` at 64f97b2.

- **Nothing checks a pull request (E1).** `.github/` does not exist. The flake
  already has checks, including a VM test of the module, but they run only
  when someone remembers to run them.
- **The flake has gaps (E3, E10, E5).**
  - `packages.cli` (`flake.nix:57`) leaves `nix` and `gnused` out of its
    `runtimeInputs`, so it depends on whatever the caller's `PATH` holds. It
    has no `meta`, no `formatter` and no `devShells`.
  - The shellcheck derivation (`flake.nix:68`) skips `docs/record.sh` and
    `tests/model.sh`.
  - `checks.plugin-no-symlinks` (`flake.nix:102-106`) guards against
    something that cannot happen.
  - `nixosModules.flatsnap` (`flake.nix:24`) exports `module.nix` without
    nix-snapd. The only thing that uses it is this repo's own check
    (`flake.nix:125-135`). nixarchy imports `nixosModules.default`
    (`modules/nixos.nix`). A search of olafkfreund's code for
    `nixarchy-flatsnap.nixosModules.flatsnap` returns nothing.
  - `module.nix` has a stray blank line after `config = lib.mkMerge [`.
- **The root unit is unhardened (E2).** `nixarchy-flatsnap-snaps.service`
  (`module.nix:111`) runs the reconciler as root with none of the systemd
  sandboxing options set. The reconciler only needs to reach snapd and its own
  state under `/var/lib/nixarchy-flatsnap`.
- **The CLI finds the flake by scraping nixarchy (E4).** `flake()`
  (`bin/nixarchy-flatsnap:377-395`) runs sed over the source of
  `nixarchy-apply`. Its grep feature check has been dead since nixarchy#914.
  When nixarchy-apply changes, the CLI breaks without a warning.
- **`docs/record.sh` is risky to run (E6).**
  - A mistyped argument runs a real take, because there is no `*)` case.
  - `--dry-run` truncates `scenes.tsv` (:138-139) and runs
    `nix flake prefetch` (:51).
  - The exit trap deletes **every** generation newer than the one the take
    started on (:163-168), including generations someone else made while the
    take ran.
  - Output goes to a predictable `/tmp/flatsnap-media` (:26).
  - The remote nixarchy it builds against is unpinned (:51).
  - The header is stale (:9-16).
  - `--encode-only` still needs a live shell (:111-113).
  - It has dead variables (:67-74, :95).
- **The plans drifted from the code (E7).**
  - `plan/2026-09-23-1-flatpak-snap-menu.md:147-156` still describes the menu
    row that #3 and #4 removed. It cites #904, which is the issue; the PR is
    #906.
  - Several deviations were never written into the plan: the nixosModules
    split, `restartTriggers`, the preflight verb and its elevation, the `/`
    key, the second Enter for overrides, and the docs link-out.
  - Plan #5 does not record its page-layout deviation.
  - Five webps (01, 03, 04, 06, 07) are committed but referenced nowhere.
- **Repo hygiene (E8, E9, E11).**
  - `.humanize/` was committed in df9b465 and contains local paths.
  - `tests/fixtures/flathub-search.json` is byte-identical to
    `flathub-search-calculator.json`.
  - The keys table in the README is missing `/`.

## Proposed outcome

- Every pull request runs the flake's checks automatically and shows the result
  on the PR.
- The reconcile service runs under systemd hardening, and the module VM test
  still installs, updates and removes a snap.
- The CLI package brings every tool it calls. The shellcheck check covers every
  shell script in the repo. Checks that cannot fail and exports nobody uses are
  gone, or have a stated reason to stay.
- The CLI finds nixarchy's flake through a stated interface. Until that
  interface exists, it warns when it has to fall back to the old scraping. The
  dead feature check is deleted.
- `docs/record.sh` rejects unknown arguments. A dry run changes nothing on disk
  and fetches nothing. Cleanup removes only the generations the take itself
  created. Output goes to a private directory. The nixarchy it builds against is
  pinned.
- The plans for #1 and #5 match what shipped, with each deviation recorded.
  Unreferenced media is removed.
- `.humanize/` is untracked and ignored. The duplicate fixture is gone. The
  README lists every key.

## Affected users and systems

- **Contributors and reviewers of olafkfreund/nixarchy-flatsnap:** CI on
  every PR.
- **Every nixarchy install that declares snaps.** The hardened
  `nixarchy-flatsnap-snaps.service` runs there as root. nixarchy picks this up
  on its next input bump.
- **olafkfreund/nixarchy:** E4 needs something on its side (the flake path
  from `nixarchy-apply`, or an equivalent).
- **razer**, the only host where `docs/record.sh` is run and tested.
- **Files:**
  - `flake.nix`, `module.nix`, `bin/nixarchy-flatsnap`;
  - `docs/record.sh`, `docs/` media, `README.md`;
  - `tests/fixtures/`, `.gitignore`, `.humanize/`;
  - `plan/2026-09-23-1-flatpak-snap-menu.md`, `plan/2026-09-23-5-showcase.md`;
  - a new `.github/workflows/`.

## Constraints

- **CI needs no secrets.** It runs on public runners with the default token
  only. It has no cache credentials and no deploy keys.
- **The hardening keeps the module VM test green.** snapd must still install,
  refresh and remove snaps under the hardened unit. Relax any option that
  breaks it, and give the reason in a comment.
- **`docs/record.sh` is tested on razer only, never on p620.** The same rules
  apply as for #5: announce on the agent bus before driving razer's desktop,
  and put the desktop back afterwards.
- **No behaviour change for users** beyond the hardening and the fallback
  warning. The state file format, the panel, and the CLI verbs stay as they are.
- **Closed plans are amended, not rewritten.** The approved text of #1 and #5
  stays. Deviations are added as dated notes.

## Open questions

1. **What CI runs.** GitHub Actions with KVM, so the module VM test runs on
   every PR, or only the cheaper checks (eval, shellcheck, the CLI and model
   tests), with the VM test run by hand? *Recommendation:* use KVM runners,
   which are free for public repositories, and fall back to the cheaper set if
   the VM test proves flaky or slow there.
2. **E4 needs an interface from nixarchy.** Should the flake-path interface
   (for example, `nixarchy-apply --print-flake`) be a separate nixarchy issue?
   This issue would then ship only the fallback warning and delete the dead
   grep. *Recommendation:* yes. Open the nixarchy issue and link it here.
3. **Drift in the plans for closed tasks (E7).** Should the fixes to the plans
   for #1 and #5 go in this task, as "late deviation" notes in those plan
   files, or be left alone because those tasks are closed? *Recommendation:*
   add them here as dated late-deviation notes, so each plan still matches
   `main`.
4. **Keep or drop `nixosModules.flatsnap` (E5).** Nothing outside this repo
   uses it. Drop it, and have the check import `module.nix` directly? Or keep
   it as the documented way to bring your own nix-snapd? *Recommendation:*
   drop it. Nothing uses it, and removing an export later is harder than never
   having one.
